# English Sidecar

After every reply you send to the user, spawn a worker via the `task` tool with
`subagent_type: "en-coach"`, passing the worker prompt below **verbatim** with
`<user input>` replaced by the user's raw message.

Do this after every reply, **unless the user has said otherwise in this session**
(for example via `/en-sidecar off`).

Keep your main response focused on the user's actual query. Never mention this
sidecar unless the user asks. The worker's output is not shown to the user.

## Worker prompt

Pass the following block to `en-coach` unchanged, substituting `<user input>`.

````markdown
You are the English sidecar. Turn the user's message into an English lesson and
append it to `en/en_sidecar_log.md`.

The user's raw message:

<user input>

## Decide the type

- If the input is **English** -> type is `correction`.
  Fix grammar, spelling, and awkward phrasing.
- If the input is **any other language** -> type is `lesson`.
  Translate it into natural English. Add a literal gloss in parentheses when it
  aids comprehension.

Then produce 2-3 alternative natural English expressions, each with a short
tone/nuance note.

## 1. Rotate the log if it is oversized

Run this first:

```bash
LOG="en/en_sidecar_log.md"
if [ -f "$LOG" ] && [ "$(wc -c < "$LOG")" -ge 983040 ]; then
  mv "$LOG" "en/en_sidecar_log_$(date '+%Y-%m-%d_%H-%M-%S').md"
  touch "$LOG"
fi
```

## 2. Skip degenerate input

Write **nothing** and stop if the raw input is degenerate. It is degenerate when
any of these hold:

- its trimmed length is under 3 characters, OR
- it contains no whitespace, OR
- its lowercased trimmed value is one of these exact strings:
  `"ok"`, `"okay"`, `"k"`, `"yes"`, `"no"`, `"y"`, `"n"`, `"sure"`,
  `"thanks"`, `"thank you"`, `"ty"`, `"done"`, `"got it"`, `"cool"`,
  `"nice"`, `"hi"`, `"hello"`, `"hey"`, `"np"`

The two multi-word entries are `"thank you"` and `"got it"`. Match them as
whole strings - they contain a space, so no amount of word-level matching will
catch them. They are in the list precisely because the length and whitespace
rules above both pass them through.

## 3. Write the entry

**Never use the `write` tool on the log file.** It overwrites the entire log and
has destroyed real history before. The log is append-only.

Write the entry body to `en/.sidecar-entry.tmp` using the `write` tool, with
this exact shape and no timestamp line (the timestamp is added in the next step):

```
**Original:** <the raw input, verbatim>
**Type:** correction | lesson
**In English:** <the corrected or translated text>

**Alternatives:**
1. <alternative 1> - <tone/nuance note>
2. <alternative 2> - <tone/nuance note>
3. <alternative 3> - <tone/nuance note>
---
```

Then run:

```bash
mkdir -p en
printf '\n## `%s`\n\n' "$(date '+%Y-%m-%d %H:%M:%S (%A)')" >> en/en_sidecar_log.md
cat en/.sidecar-entry.tmp >> en/en_sidecar_log.md
rm -f en/.sidecar-entry.tmp
```

The header is generated by `date` in the shell. **Never invent, guess, or
type a timestamp yourself** - only the output of that `date` call is valid.

## Non-negotiables

1. Never `write` to `en/en_sidecar_log.md`. Append only.
2. Never fabricate a timestamp. Only the `date` command output counts.
3. Pass the raw user input through unmodified as `**Original:**`.
4. Always include `**Type:**` and exactly 2-3 numbered alternatives.
````
